# 研究方向

`Automate/` 是在 Python 里低成本消除未知数的研究场地，`score-pdf-to-gp`（`score-pdf-to-gp`）是尚未定形的产品仓库，形态由这里的结论决定。

## 硬规则

| 规则 | 说明 |
| --- | --- |
| 不参考 PDF 附带的笔记 | 同目录 `.txt`（如 `空港曲 - 宋冬野 (笔技).txt`）不是生成资料，任何时候都不作为 pattern 或音符来源。所有内容从谱面推导 |
| 脚本不做解读 | 遇到不确定必须输出「我不知道」并标出位置，交给模型或人处理，不能猜一个值填上 |
| 评估以全库为准 | 单文件调参会过拟合，`Alfyn's Theme` 单文件闭合率 33% 时全库只有 19.4% |

## 两条读取路径

| 路径 | 适用输入 | 数据来源 | 弦位归属 | 状态 |
| --- | --- | --- | --- | --- |
| 文本层 | `qt-export`，少数 `mixed` | PDF 内容流的定位字形与矢量线段 | 位置由 PDF 直接给出，零误差几何匹配 | 端到端跑通，精度未达标 |
| 图像 | `image` / `vector` / `text` / 多数 `mixed` | strip 切片渲染图 | 需先检出六线 y 坐标 | 未实现 |

信息轨分工：

| 类别 | 输入 | 用途 |
| --- | --- | --- |
| B | 六线谱 TAB | 主线，读出已印在纸上的弦位与品位 |
| A | 五线谱或钢琴谱 | 仅作时值补充源，当 TAB 不带完整节奏时使用 |

A 降级为时值来源后不需要完整 OMR 与 pitch 到 fret 的映射，`score-pdf-to-gp` 的 todo.md 里由 oemer 带来的三项风险（portable Python embed 选型、ML 权重裁剪、单页推理耗时）随之失效。

一页上可能同时存在多条信息轨，《空港曲》第 1 页就同时有六线谱、TAB 下方的符干与 beam、简谱行三条。时值取自哪条轨，因谱而异。

## 文本层路径：已解决的部分

### 解码链

| 环节 | 做法 |
| --- | --- |
| Qt 每个字形一个 `Tj`，前置 `Td` | 每个字形位置精确可得 |
| 字体子集编码 `<0001>` | 经 ToUnicode CMap 还原为字符 |
| 内容流的 `cm` / `Tm` / `Td` | 最小解释器跟踪 CTM 与文本矩阵，得设备坐标 |
| 路径算子 `m` / `l` / `re` | 同一解释器输出线段，得谱表线与小节线 |

### 字体分工

| 字体 | 承载 |
| --- | --- |
| `GPBravuraRegular` | 音乐符号（SMuFL）：符头 `U+E0A4`、附点 `U+E1E7`、谱号 `U+E050`、拍号 `U+E084`、临时记号 `U+E262` |
| `ArialNormal` / `ArialRegular` | TAB 品位数字与括号，括号表示虚拟音 |
| `TimesNewRoman*` | 标题、编配者、tempo、`let ring` 等文字 |

### 弦位归属

每个 TAB 谱表恰有 6 条线，间距 6.38 点。品位数字基线固定落在所属弦线下方 4.0 点，偏移量全局一致。程序自动标定后退化为一次最近邻匹配。

复核：`Alfyn's Theme` 第 1 系统 TAB，标定偏移 -3.30，measure1 全部 22 个字形距所属弦线 0.88 到 0.95 点，容差 2.0 点下无一例歧义。

### 小节线

判据：竖线同时跨满 TAB 谱表与其配对的五线谱。符干只跨五线谱，符杠只跨 TAB，交集后剩下的即小节线。

| 细节 | 处理 |
| --- | --- |
| 小节线常跨整个系统一笔画完 | 不设长度上限，仅在无配对谱表时才按单谱表跨度设限 |
| Qt 用细矩形描小节线 | 同一条出现两次，相距约 0.7 点，需去重 |
| 页边被误判为小节线 | 按谱表自身横向范围裁剪 |
| 谱表左端不是竖线 | 需显式补入作为首条小节线 |

### 五线谱侧时值

信号取自 `Alfyn's Theme` 第 1 页第 1 系统：

| 信号 | 数据 |
| --- | --- |
| 符头 `U+E0A4` | 83 个，分布在 41 个 x 位置 |
| 符干 | 竖线，长度 17 到 28 |
| 符杠 | 谱表外短横线 35 条，按 y 分层：上方 294 到 304，下方 265 到 271 |
| 附点 `U+E1E7` | 41 个 |

判据：

| 环节 | 判据 |
| --- | --- |
| 符干 | 与谱表 y 区间相交的竖线，排除已知小节线的 x |
| 符杠 | 谱表外的近水平线段（倾角小于 25 度），成对边构成一个填充多边形，宽度上限为谱表横向跨度的 35% |
| 音符列 | 每个符干一个节奏事件，符头按 x 距离不超过 7 点归入最近符干 |
| 时值 | 符杠层数：0 为四分，1 为八分，2 为十六分，3 为三十二分 |
| 附点 | 符头右侧 7 点内的 `U+E1E7`，按 x 去重，上限 2 |

x 间距不能用于推时值：实测相邻 x 间距为 7.9、10.0、12.5、17.6 等，非 1:2:4 量化，制谱用的是对数式排版。

### TAB-only 侧时值

Guitar Pro 把节奏画在 TAB 谱表**下方**，覆盖 403 个 TAB-only 系统：

| 标记 | 含义 |
| --- | --- |
| 符尾字形 `U+E240` 到 `U+E24F` | 未连杠音符的时值，`U+E240` 为八分，每档加两个码位 |
| 符杠多边形 | 连杠组的时值，按层数 |
| 两者皆无 | 四分或更长 |

符干画在品位数字右侧约 1.9 点处。符杠覆盖判定必须用符干 x 而非音符 x，容差 1.5 点，否则短钩会蹭到相邻音符，把八分误判成十六分。

### 拍号读取

`timeSig` 数字在同一 x 上下堆叠，上为分子下为分母。`Alfyn's Theme` 全页只有一组，位于第一系统起始处，读出 4/4。注意 `Fraction(4, 4)` 会自动约分为 1，比较时无碍，仅显示需要单独保留分子分母。

### 小节时值闭合校验

`rhythm.py --check` 逐小节加总时值并与拍号比对，不依赖人工基准。判据：合计等于拍号，或各声部分别等于拍号，二者满足其一即算闭合。

时值序列一致与小节闭合几乎完全同步，闭合校验是可靠的代理指标，在没有 `.gp` 的文件上可以继续用。

| 范围 | 闭合 |
| --- | --- |
| `Alfyn's Theme` 第 1 页（调参对象） | 4 / 12 |
| 全库 qt-export 有配对五线谱的部分 | 67 / 345 = 19.4% |

分文件闭合率差异极大：

| --- | --- |

| 南山南 - 马頔 | 12 / 21 |

## 文本层路径：剩余误差

| 缺口 | 说明 |
| --- | --- |
| 次符杠与短钩 | 单符干上的短钩可能被漏计或与主符杠合并，当前最可疑的误差来源，也是 TAB-only 连杠组内部的主要误差 |
| 多声部 | 符干方向已实测不能代表声部，需另找判据。可先按「合计接近拍号的一倍还是两倍」判断声部数 |
| 休止符 | Bravura 码位 `U+E4E3` 到 `U+E4E8` 未纳入时值累加 |
| 延音连线 | 五线谱侧画符头而 TAB 侧省略品位数字的事件，是否计入时值未定 |
| 孤立符头 | 未能关联到符干的符头，处理规则尚未收敛 |
| 拍号 | 硬编码 4/4，应统一从 `timeSig` 码位读取 |
| 小节切分偏移 | 开头多切或少切一格，整首错位，南山南是典型 |
| 弱起小节 | 未处理，直接判为不闭合 |

误差是局部而非结构性的。例：`Alfyn's Theme` system1 measure1 得 19/16，期望 16/16，只多出约一个八分，对应一到两个符干的符杠层数少计了一层。事件检测已确认正确，误差在时值赋值。

两侧事件数天然可能不等，TAB 事件位置不能直接当作节奏栅格：

| 侧 | 事件数 | x 位置 |
| --- | --- | --- |
| 五线谱 | 11 | 66.2, 87.8, 100.2, 114.7, 125.1, 144.7, 157.2, 174.8, 187.7, 205.3, 217.8 |
| TAB | 9 | 69.1, 90.6, 115.5, 128.0, 158.0, 175.6, 188.1, 205.7, 218.1 |

x≈100.2 与 x≈144.7 两处无 TAB 对应，逐一核对矢量后确认两者都有独立符干与符头，是真实事件而非误检。推测是延音连线的后半，尚未验证。

## 图像路径：现状

### 切片粒度：strip row

单小节切片约 140×110 像素，尺寸太小需放大，而放大把省下的 token 全部吐回去。正确粒度是一个系统一张图，保留原生分辨率不放大。

一个 strip 的范围：和弦图 + 六线谱 + 下方符干扫弦记号，不含简谱行与歌词。

在 1105×190 原生分辨率下，以下元素全部可辨：和弦名、和弦图指位、品位数字、`×` 闷音记号、`P` 勾弦标记、符干与扫弦分组。

### token 实测

公式：`tokens ≈ 宽 × 高 / 750`。当前模型长边上限 2576 像素，单图上限约 4784 tokens，1280×1810 的整页不会被缩放。

| 方案 | 尺寸 | 单张 tokens | 一页合计 |
| --- | --- | --- | --- |
| 整页 | 1280×1810 | 3089 | 3089 |
| **strip @1x** | 1105×190 | **279** | **1116（4 条）** |
| strip @1.5x | 1657×285 | 629 | 2516（4 条） |
| 单小节 @1x | 140×110 | 20 | 656（32 个） |
| 单小节 @3x | 420×330 | 184 | 5888（32 个） |

strip @1x 是唯一同时满足可读与省 token 的点，约为整页的三分之一。

### strip 批量：token 中性

多条 strip 拼成一张图与分多张发送，token 完全相同。image token 只按面积计算，拼接不产生规模效应。素材：第 3 页，每条 strip 1105×183。

| 条数 | 尺寸 | 缩放 | tokens | 每条 |
| --- | --- | --- | --- | --- |
| 1 | 1105×183 | 1.000 | 269 | 269 |
| 2 | 1105×366 | 1.000 | 539 | 270 |
| 3 | 1105×549 | 1.000 | 808 | 269 |
| 4 | 1105×732 | 1.000 | 1078 | 270 |
| 5 | 1105×915 | 1.000 | 1348 | 270 |
| 14 | 1105×2562 | 1.000 | 3774 | 270 |
| 15 | 1105×2745 | 0.938 | 3561 | 237 |
| 20 | 1105×3660 | 0.704 | 2671 | 134 |

拐点在 N=15：堆叠高度 2745 超过长边上限 2576，触发缩放，token 下降但分辨率损失约 6%。一页只有 4 到 5 条系统，实际场景永远不会到达该拐点。

整页对照：整页 3089，5 条 strip 合计 1348，差额 1741，来自简谱行、歌词、页边距与页眉。

既然 token 中性，每张图放几条 strip 只需权衡精度：

| 单条 | 多条（3 到 5） |
| --- | --- |
| 无跨条位置漂移，一次只对齐一组六线 | 能看到跨行的和弦延续 |
| 单次输出短，出错影响面小 | 一次拿到整页结构，段落重复更易识别 |

### 图像质量

《空港曲》第 1 页灰度分布：纯白 88.76%，纯黑 1.50%，共 255 级灰度。这是带抗锯齿的干净矢量渲染，不是噪点扫描。锐化与对比增强收益有限，真正影响可读性的变量是放大倍数，而放大与省 token 直接冲突。

### 几何定位已跑通，字形识别未跑通

| 环节 | 状态 | 数据 |
| --- | --- | --- |
| 六线 y 坐标检出 | 可用 | 366 / 380 / 393 / 407 / 420 / 434，间距 13 到 14 像素 |
| 小节线 x 坐标检出 | 可用 | 109 / 325 / 466 / 606 / 746 / 886 / 1029 / 1170 |
| 字形连通域检测 | 不可用 | 第 1 小节检出 25 个 blob，实际字形约 6 到 12 个 |

连通域噪声主要来自下方符干与括号串入，尺寸多为 `2x13` `1x13` 的细长块。按「距最近弦线偏移」过滤后信号明显（偏移 ≤4 像素的才是真字形），但仍有重复与碎片。

小节线检测原始输出另含杂讯：系统括号被计为小节线，反复记号 `‖:` 的粗双线被计为两条，开头小节线与括号粘连。

### 模板匹配是识别层的方向

字形词汇表极小：`0` 到 `9` 加 `×`，共十一个符号，且同一份谱字体完全一致。取一次样本后匹配其余，精度可接近 100%。

分工：脚本负责定位与切分字形，模板匹配负责识别，只有置信度低的字形才切图交给模型，模型的图像输入接近零。

文本层输出可直接充当模板匹配的训练与验证基准，覆盖 37 个文件。

### 段落去重是降 token 的主杠杆

| 来源 | 机制 | 量级 | 状态 |
| --- | --- | --- | --- |
| 固化格式知识 | 不再每次重新逆向 gpif | output 大头 | 已实现 |
| 段落去重 | 从图像识出重复段落，只描述唯一段落，重复处用引用 | 见下 | 未实现 |
| 输入切片 | 脚本按几何切出 strip row，模型不读整页 | 图片是 input 大户 | 已测 |

| 观测 | 值 |
| --- | --- |
| 《空港曲》生成小节数 | 24 |
| 双小节单元数 | 12 |
| 唯一 pattern 数 | 8 |
| Guitar Pro 保存后 Note 去重结果 | 144 收敛到 17 |

信息量正比于唯一段落数，不是小节数。token 消耗应当按唯一段落计。

## 真值与回归基准

库里 11 首歌同时存在 `.gp` 与同目录的 qt-export PDF，两者构成输入输出配对，是不依赖人工标注的真值集。

`gpread.py` 读取 `.gp` 的每小节每声部时值与音符。`行星 - 理想混蛋` 的 `.gp` 95 小节全部时值闭合，确认读取器本身可靠。

任何改动都要跑一遍这 11 组，防止过拟合。

## 踩过的坑

| 坑 | 现象 | 修正 |
| --- | --- | --- |
| 谱表读取顺序颠倒 | PDF 的 y 越大越靠上，聚类按 y 升序输出等于从页面底部往上读，整页小节顺序错乱。这一个 bug 使小节音符集合一致率停在 9.9% | `find_staves` 返回前反转，多个文件从零匹配跳到九成以上 |
| 弦号反转 | 六线谱顶线是 1 弦，`string_of` 却返回 6 | 索引直接加一，不再用总数相减 |
| 小节号被读成品位 | 小节号是 `TimesNewRomanRegular`，品位数字是 `Arial*`，两者 y 接近 | 品位数字限定 Arial 字体 |
| CMap 数组形式 bfrange | `<lo> <hi> [<d0> <d1> ...]` 最初被漏解析，是文本层的第一个坑 | 补上数组分支 |
| 长符干被误判为小节线 | 低音符的符干跨满整个谱表，与小节线同形，「跨满谱表」判据把它们全排掉，41 个音符列只找到 11 个符干 | 改为排除已知小节线的 x |
| 系统级横线被误判为符杠 | 一条 x 85 到 551、宽 466 的横线覆盖几乎所有符干，每个音符少一档时值，全页呈现为十六分与三十二分 | 符杠宽度上限设为谱表横向跨度的 35% |
| 短钩被长度下限过滤 | 符杠边最小长度设为 4.0，短钩实测长 3.74，整组被丢弃，附点八分加十六分被读成两个八分 | 下限降到 2.5 |
| 符杠归属不分上下侧 | 上行符干把谱表下方另一组的符杠也计入，时值整体少一档 | 按符干自由端所在侧过滤。斜符杠的存储 y 是中点会越过符干末端，自由端不能设距离上限，侧向是唯一可靠的界 |
| 孤立黑符头兜底为全音符 | 一个顶 16/16，单小节膨胀到 63/16 | 黑符头改为按 x 邻近二次关联，仍失败则丢弃，只有空心符头才是真全音符 |

被推翻的假设，各留一行备查：

| 假设 | 推翻依据 |
| --- | --- |
| TAB-only 系统无节奏信息 | 起因是谱表顺序颠倒查错了谱表。节奏画在 TAB 谱表下方，符尾字形加符杠多边形 |
| 符干方向代表声部 | `Alfyn's Theme` measure1 按方向拆分得 v1 = 9/16、v2 = 5/8，都不闭合到 4/4。单声部指弹会依音高自动切换符干方向 |
| 弦位归属是识别瓶颈 | 只对图像路径成立。文本层路径下字形位置由 PDF 直接给出，是零误差几何匹配 |
| 谱表上方 Bravura 字形是逐音符节奏记号 | `行星` 实测 `U+E858` 82 个、`U+E85A` 59 个、`U+E859` 28 个加 28 个附点，用闭合率反解映射最佳只到 4/24 = 16.7%，且某系统 9 小节只有 6 个字形。TAB 谱表上下 30 点内的竖线仅 2 到 3 条、长度 10，也不是符干 |
| 精度问题源于分辨率 | 《空港曲》修正的 7 个小节里 6 个错误源于用笔记的文字描述推断而非读图，无一由图像质量导致 |
| 单读者自评可作精度基准 | 建立 ground truth 与执行测试是同一读者，先看过高倍放大后再读低倍即为回忆而非识别。改用 `.gp` 配对与闭合率作独立基准 |

## 三层拆分与设计原则

| 层 | 内容 | 谁产出 | 每首成本 |
| --- | --- | --- | --- |
| 形式层 | pattern 语法、段落语法、技巧编码、音高换算、ZIP 与 XML 写入 | 一次性 | 0 |
| 实例层 | 某首歌的 pattern 定义与段落编排，全部从谱面推导 | 模型 | 小 |
| 校验层 | 文件合法性、形式一致性 | 一次性 | 0 |

现有归属：`gpwrite.py` 属形式层，`verify.py` 属校验层，`kongangqu.py` 是实例层但尚未与形式层分离，曲子数据与 pattern 语义混在同一个 `.py` 里，换一首歌要重写整份文件。`kongangqu.py` 现有 pattern 定义来自笔记，来源不合法，需从谱面重新推导后替换。

实测：《空港曲》修正的 7 个小节里，6 个是解读错误，执行错误 0 个。执行层（ZIP、XML、id 分配、音高换算、时值闭合）全对。

`verify.py` 目前只验文件合法性（悬空 id 引用、小节时值闭合），还需补形式一致性校验：同一段落多次出现时各次内容是否真的一致。

### 四项改动

| 改动 | 做法 | 效果 |
| --- | --- | --- |
| 小节闭合 + 水平间距解歧（`src/score/rhythm_tab.py` 的 `resolve`） | TAB 里 level 0 表示无符尾无 beam，Quarter / Half / Whole 长得一样。用两个约束定值：小节必须凑满拍号，制谱的水平间距正比于时值。枚举能凑满的组合，取比例最贴合间距的那个 | values 39.6% → 50.8% |
| 延音拍补全（`stems_under` / `tied_columns`） | GP 的 TAB 导出对 tie 的目标音不画品位数字，只留符干，我们整拍丢失。改成扫描节奏带里的符干，有符干无数字的 x 按前一拍音高补一拍。实测某曲 96 个 Note 里 24 个带 Tie、9 个是 destination | notes 55.0% → 65.5%，values → 71.6% |
| `drop_slivers` 改用 75 百分位（`src/score/staff.py`） | 原本用中位数当基准宽度，但一个系统里碎片可能比真小节还多，中位数本身就是碎片，于是一个都删不掉。阈值 `ratio=0.35` | notes → 78.9% |
| 基准口径修正（`tools/bench.py`） | 原本只比对 voice 1，解码器不分声部，第二声部必然被判成多音符。改成音符比对合并全部声部，时值只在单声部小节上统计，多声部数量单列一栏 | 口径修正，非精度提升 |

`drop_slivers` 阈值扫描过 0.30 / 0.35 / 0.40 / 0.45 与「只删首尾」变体，0.35 到 0.40 是平台（差异 0.1% 属噪声），0.55 会崩到 59.6%。

另修：`src/convert.py` 的 `decode` 调 `measure_sequence` 时漏传拍号，产物路径上闭合解歧从未生效，修好后 `行星` 才达成零误差往返。

### 被数据否掉的方案

曾假设 beam 层级多数一层是因为伪 beam 混入，想用「堆叠连续性」几何判据剔除，依据是真 beam 贴着叠，间距约 1.5 倍自身厚度。1341 个样本测下来，间距 / 厚度比在正确样本（1202 例）和错误样本（89 例）里完全重叠，都是 1.5..2.49，阈值只会从正确样本中间切过去，实测 values 掉到 28.8%。已回退。

beam 覆盖计数本身已有 91% 正确率，几何这条路走到头了，后续提升要靠正交信息。
