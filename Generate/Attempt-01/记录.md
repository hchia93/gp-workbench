# Attempt-01 转换记录

曲目: 烟瘾 - 胡凯儿
来源: Guitar Pro 导出 PDF, 经 macOS Quartz 重排, 7 页 79 小节
目的: 记录有效/无效方法, 后期编译成模板 how-to

## 1. PDF 形态识别

| 判定 | 方法 |
| --- | --- |
| Guitar Pro 导出 | fonts 出现 GPBravura |
| 被 mac 重打包 | Producer = "macOS Quartz PDFContext", Qt 原始结构丢失 |
| 路线选择 | 唯一标准: 文本层能否读出品位数字, 不看 Producer 字段 |

## 2. Quartz 适配

三件事全部必须:

| 项 | 有效做法 |
| --- | --- |
| 文本层 | tokenizer 同时收 `( )` literal (Quartz) 与 `<hex>` (Qt), literal 处理八进制转义 |
| 字体 | 无 ToUnicode 的 TrueType + MacRomanEncoding, ASCII 区直接 chr(code) 恢复 |
| 坐标 | 页面 300dpi (2480x3508), staff 阈值按 595 宽标定, 先按 MediaBox 归一化再跑几何分析 |

无效: 直接跑现有 pipeline, route 判 no-staff, 全零。

## 3. 矢量记号检测

Quartz 把字形转曲, 文本层拿不到记号, 走几何检测。

关键方法(最有效): render.py 把解析出的 segment/glyph 重绘 PNG 人眼目验, 所有歧义(repeat dots vs 附点, 𝄎 vs double bar, П/V 分类)靠渲染定案, 纯数值推理会错。

| 记号 | 特征 |
| --- | --- |
| repeat barline | 填充矩形粗线(宽约 0.8pt, 普通线 0.35) + 垂直排列双圆点, 左点=`:\|`, 右点=`\|:` |
| two-bar simile 𝄎 | 跨小节线绘制, 两圆+双斜线, 特征=两侧小节完全无音符 |
| volta | 数字带句点 "1." "2." + bracket 横线, bracket 起点 x 决定覆盖小节 |
| 段落框 | Bold 文本, x 对齐实际所属小节, 不总在行首(Chorus I 在 m27, Chorus II 在 m52) |
| double bar | 两条细线间距 2-3.5pt, repeat 组合处(double + `\|:`)拆开识别 |
| pickstroke П/V | 形状级判定: П 有直立竖边(dx<1.2)+顶横, V 是两条倾斜长边(dx≥1.2)无横段 |

| 无效 | 原因 |
| --- | --- |
| 按段方向计数分类 П/V | 端帽碎微段淹没长边, V 全被误判成 Down |
| 按 y 固定带检测 | page0 和弦图与记号带重叠, 要用二维聚簇 |

## 4. tie 判定

| 结论 | 内容 |
| --- | --- |
| 无效 | "有 stem 无数字"一律当 tie, 扫弦段 slash 列同样无数字, 全被误 tie, 弧线泛滥 |
| 有效 | tie 必须有弧线佐证, 弧线=连续曲线段链, 宽 7-50pt 高 0.8-6pt, 端点对齐两列 |
| slash 扫弦列 | 音符复制前列(重新发声), 不加 tie |

## 5. 展开语义

| 项 | 结论 |
| --- | --- |
| "展开"含义 | 仅指 simile 记号, 𝄎 用前两小节内容替换 |
| repeat / volta | 保留 GP 标记形态, 不物理展开 |
| 无效 | repeat 全部物理展开成 105 小节线性谱, 返工收回 79 小节 |
| 最终形态 | PDF 小节数 1:1 + repeat/volta/section 标记 + simile 实体化 |

## 6. .gp 文件手术

针对 GP 保存过的文件:

- GP 保存会把相同内容的 Bar/Voice/Beat/Note 去重共享(105 小节只剩 78 个 beat), 改任何一处必须 clone-on-write 沿链克隆: MasterBar→Bar→Voice→Beat→Note
- 大坑: `<Bars>` 等标签既是 MasterBar 里的引用行又是顶层池容器名, 正则必须锚定 `<Bars>\s*<Bar id=`, 否则贪婪匹配毁掉整个文件
- 孤儿池条目(删小节后不再被引用)无害, GP 打开会清理
- 每次手术前备份
- 用户在 GP 中开着文件时 patch, 需用户关闭重开, 否则 GP 内存旧版覆盖补丁

## 7. BinaryStylesheet 格式

- .gps 是文本 Key=Value
- .gp 内 Content/BinaryStylesheet 是二进制: u32 BE 条目数 + [u8 keylen][key][u8 type][value]

| type | 值 |
| --- | --- |
| 0x00 | bool (1B) |
| 0x01 | int32 BE |
| 0x02 | float32 BE |
| 0x03 | string (u16 BE len + utf8) |
| 0x07 | RGBA (4B) |

合并方法: 按 binary 里已有键的 type 编码 gps 文本值替换, 591 键中 590 命中。

## 8. gpif 标记语法速查

| 标记 | 语法 |
| --- | --- |
| Repeat | `<Repeat start="true\|false" end="..." count="N" />` |
| Volta | `<AlternateEndings>1</AlternateEndings>` |
| Section | `<Section><Letter>CDATA</Letter><Text>CDATA</Text></Section>` |
| DoubleBar | `<DoubleBar />` |
| PickStroke/Brush | Beat Properties 里 `<Property name="PickStroke\|Brush"><Direction>Down\|Up</Direction></Property>` |
| Tie | Note 开头 `<Tie origin="bool" destination="bool" />` |

MasterBar 内元素顺序: Key, Time, Repeat, AlternateEndings, Section, DoubleBar, Bars。

## 9. 协作流程

- 用户在 GP 里手修 + 增量 patch 直接覆盖 Dropbox 文件, 交替迭代
- 用户先手动做一个样例标记(如 bar33 的 PickStroke Up) = XML 格式参照, 比口头描述准
- 已知短板如实报告: 扫弦段 stem 缺列 → 时值不闭合 + 179 个 stroke 挂不上

## 10. 扫弦小节模板法

第二轮核心增量: 扫弦小节的节奏不靠 beam/stem 解码(stem 断裂缺列是时值不闭合的根源), 靠拨弦记号 x 间距推断。

| 间距 | 时值 |
| --- | --- |
| ~40pt | 四分 |
| ~20pt | 8分 |
| ~10.5pt | 16分 |

全曲扫弦小节收敛为少数模板:

| 模板 | 节奏型 |
| --- | --- |
| T1 | (8,8)(8,16,16)×2, 10 列, 换和弦在 idx5 |
| T2 | (8,8)(8,16,16)(16tie,16,8)(8,16,16), 11 列 |
| T2Q | T2 变体, 首拍换四分: (4)(8,16,16)(16tie,16,8)(8,16,16), 10 列 |
| T3 | 四分×4, 每拍换和弦 |
| T4 | 8分×7 + 16分×2 |
| T6 | 16分×16 连奏, PS 序列逐小节照渲染抄 |
| T7 | (8,16,16)×4, 四和弦 |
| T8 | (16×4)(8,16,16)×3, 13 列, Outro 前段主型 |
| T8T | T8 拍3 tie 变体: (16×4)(8,16,16)(16tie,16,16,16)(16×4), 15 列 |
| T9 | (16.,16.,16,4)×2, 附点 riff 型 |

| 规则 | 内容 |
| --- | --- |
| T2 识别特征 | U 记号后 ~31pt 空档 = tie 列(П) + 被括号挤住的 V + 8分列, 检测器漏但模式必然 |
| 恒定偏移 | 记号中心 = 数字列 x + 2.3pt, 和弦图左缘 = 列 x + 10.5pt, 先量偏移再匹配, 全部 d<0.5 |
| 换和弦点 | 数字列(有品位数字的列) |
| 同构型小节 | 直接复用 note 池引用 |
| tie 列括号记号(П) | 用户约定标为 PickStroke Down |
| 证据合并容差 | 4pt(数字列并入记号列), 否则产生假 16 分列 |

## 11. 和弦图解码

| 项 | 方法 |
| --- | --- |
| 网格竖线 | 先按 y_top 聚行再按 x 间距分 run(6 条, 间距 ~5pt), 避免不同行同 x 干扰 |
| 指位 | 图内实心圆, string=最近竖线, fret=行号 |
| O/X | 图顶上方 O=开放, X=禁弦, X 的斜段碎片会污染 O 判定, mute 优先 |
| 命名 | 不拼文本(分词不稳), 用指位构型→名字映射表(构型唯一) |
| 同名不同构型 | E/G# 开放版 vs 低音版, 在 DiagramCollection 里作为不同 id 的 Item 共存 |
| 高把位 | D5=x577 用 baseFret 表达, 图右侧的品位数字是 base 标记 |
| 挂接 | 图左缘 x + 10.5 → 最近列 → beat, simile 小节的和弦=源小节同位复制 |
| gpif | DiagramCollection 与 DiagramWorkingSet 两处都加, beat 挂 `<Chord><![CDATA[id]]></Chord>` 在 `<Notes>` 前 |

## 11.5 细粒度识别补遗

| 项 | 内容 |
| --- | --- |
| 附点识别 | TAB-only 模式下附点印在 stem 旁下方的小圆(不在数字旁), 出现于 beam 区上方 |
| base 品号 | 高把位和弦图(A5=577, D5=577 型)在图右侧标品位数字, gpif 写 baseFret=品号-1 |
| 换和弦列定位 | 模板列 x 未知时, 图 x 在小节内的比例 ≈ 目标列的时间比例(idx4≈0.31, idx7≈0.54, idx10≈0.77 for T8), 比例法可靠 |
| 批量重建 | 模板参数化(values/ps/tie 位/digit 槽位) + 每小节一行 PLAN 表, 数据驱动一次重建 21 小节全部闭合 |
| 全曲验证器 | 逐小节时值求和 + 全池 dangling 引用检查, 每次 patch 后必跑 |
| 扫弦型复用 | 同一首歌扫弦型高度重复, 渲染定一个模板, 同型小节批量套用 |

## 12. 协作与安全

- clone-on-write 的引用计数必须把克隆体的子引用也计入(克隆 Beat 时其 Notes 的 refcount+1), 否则修改泄漏到共享对象, tie/pickstroke 曾因此泄漏全曲, 只能从干净备份全量重放修复
- 用户 GP 开着文件时 patch 会被 GP 的下一次保存覆盖, patch 前确认用户已保存并关闭, patch 后用户重开
- 每次 patch 前备份, 发现污染宁可从最早干净基线重放, 不在污染文件上叠补丁
- 用户手动做一个样例(bar33 的 PickStroke Up)比口头描述格式更准
- 验证"物理块数"与"逻辑挂接数"是两回事: 共享 beat 上的和弦被多个 bar 复用是正确语义
