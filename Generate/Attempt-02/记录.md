## 2. 硬结论

| 项 | 结论 |
| --- | --- |
| BPM | 真实 72.1, autocorrelation 与 onset 最小二乘两法一致, 误差 20 ms |
| grid.json | bar_seconds 实为半小节, downbeat 偏 6 个十六分, 文件已删 |
| 前奏节奏 | 均匀八分, T-23 交替, 拇指单低音 + 二三指双音, 乐句收尾出四分 |
| 三音堆 | 转录把泛音叠进来的, 删 |
| 八度对 | 如 G2+G4, 是拇指与高音的真实音程, 不可当泛音删 |
| 弱拍音 | 本来就弱, 不能用振幅当真假判据, 用宽松阈值补空位 |
| bar 6 后半 | Bm7 -> A, 接 G#m7b5 -> G, 即 vi-V-#iv°-IV, 低音半音下行 B-A-G#-G |
| 前奏低音换和弦处 | Dmaj7 上声部 A3+C#4, 低音是 D3 不是 B2 |

## 3. GP8 文件层事实

| 项 | 事实 |
| --- | --- |
| Beat / Voice 共用 | 内容相同的 `<Beat>` 与 `<Voice>` 会被共用 id, 原地改 beat 必须先克隆 |
| 和弦图存放 | `DiagramCollection`, `ChordCollection` 为空, 属性名 `barsStates` |
| beat 引用和弦 | `<Chord><![CDATA[id]]></Chord>` |
| DiagramWorkingSet | 页面顶部的和弦表, 留空则不显示 |
| Note 属性 | 按字母序, `Tie` 是 Note 的第一个子元素 |
| 谱表可见性 | `PartConfiguration`, 02 只 TAB, 03 五线谱加 TAB |
| 版式 | `LayoutConfiguration` |
| 和弦图排版键 | `BinaryStylesheet` |
| GP8 样式表采信 | 只采信 GP8 自己编译出的样式表。GP7 时代的 `BinaryStylesheet` 塞进 GP8 文件能打开, 能显示只 TAB, 谱内不画和弦图 |
| .gps | 文本 key=value, 与 `BinaryStylesheet` 二进制格式不通, 不能直接塞。在 GP8 里加载一次再存档, 样式表才生效, 之后拿这份文件当 `apply_style --from` 参考或抽成 resource/style/gp8 |
| .gps 与二进制表 | 键集相同, `drawChordInScore=True`, `ChordDiagramPriority=3000` 两边可互相印证 |
| 歌词 | 按有音 beat 顺序发 token, 空 token 跳一拍, 多字可挤一个 token |

## 5. 冷启动步骤

1. `pip install --user numpy scipy yt-dlp imageio-ffmpeg`
2. `pip install --user torch torchaudio --index-url https://download.pytorch.org/whl/cpu`
3. `pip install --user demucs`
4. `pip install --user onnxruntime`, `pip install --user --no-deps basic-pitch`, `pip install --user pretty_midi mir_eval librosa resampy`
5. `python src/tools/chord-finder/fetch_audio.py --url <链接>`
6. `python src/tools/chord-finder/stem_split.py --in build/audio/raw.webm --seconds 40`
7. `python src/tools/chord-finder/transcribe_stem.py build/stems/htdemucs_6s/input/guitar.wav <template.gp> build/gp/draft.gp --start 5.5 --end 32`
8. 在 Guitar Pro 里手改草稿, 保存
9. `python src/tabulator/init_tabulate.py in.gp out.gp --title ... --artist ... --tempo 72 --key D`
10. `python src/tabulator/apply_style.py in.gp out.gp [--from reference.gp] [--format gp7|gp8]`
11. `python src/tabulator/inject_chord_diagram.py in.gp out.gp [--chart]`
12. `python src/tools/chord-finder/vocal_syllables.py vocals.wav --bpm 72.1 --phase 0.045 --grid0 22 --json build/vox.json`
13. `python src/tabulator/inject_lyrics.py in.gp out.gp lyrics.json [--raw]`

Python 3.13 下 basic-pitch 直接装会依赖冲突, 第 4 步必须分三条。音频与草稿落在 build/, 已 gitignored。template .gp 仓库不附带, 自备。样式集随仓库在 resource/style/, 第 10 步按目标 `<GPVersion>` 自动选 gp7 / gp8, 只有 `--from` 才需要参考 .gp。

## 11. chroma 路线记录

代码已删。240 模板 (20 种品质乘 12 根音), 非对称匹配 (缺和弦音重罚, 多余音轻罚, mean 聚合), 品质先验, 移动中位数平滑。

| 轮次 | 做法 | 结果 |
| --- | --- | --- |
| 一 | 非对称匹配 | sus 占 72%, 无三度模板挤掉三和弦 |
| 二 | 加品质先验 | sus 压到 5-17%, 大小三度混淆回到 19-21% |
| 三 | 移动中位数 | diatonic 67.2 到 73.0, clash 21.7 到 14.2 |

瓶颈始终是三度音的可靠性, 不是模板数量。三轮均在原混音上做, 「sus 是模板伪影」被分轨证据推翻, 见第 16 节。幅度谱开方压缩使 F#/F 判别比从 1.89 掉到 0.97, 大小三度不可分, 保持线性幅度。

## 12. 无效方法: 截图估读时间戳推 BPM

| 项 | 内容 |
| --- | --- |
| 数据来源 | 时间戳从截图像素量得, 误差 +/-0.3 秒 |
| 信噪比 | 一拍 0.5 到 0.8 秒, 噪声大于信号 |
| 纯网格搜索的陷阱 | 格子越密残差自动越小, 不设基线时 240 BPM 拿第一名 |
| 基线对比法 | 真实 onset 与 200 组随机 onset 在同一网格上比残差, gain 全部落在 +/-0.035 秒内 |
| 后果 | 143.6 BPM 与 downbeat 0.585 由它得出, 写进 grid.json, 均被真实音频证伪 |

结论: 时值分析只能用真实音频。

## 16. sus 结论反转

原混音上判定 sus 是模板伪影, 分离出吉他轨后证据反转。treble chroma 占该帧能量比, 噪声底约 4-6%:

| 位置 | 三度 | 特征音 | 判定 |
| --- | --- | --- | --- |
| A 三处 | C# 11-17%, 噪声底 3-4 倍 | - | 大三和弦成立 |
| 结尾 D | F# 17% | - | 三度真实 |
| Dsus2 | F# 2-3%, 低于噪声底 | E 8-12% | sus2 真实 |
| Dsus4 | F# 5% | G 16% | sus4 真实 |
| Asus4 | C# 6%, 接近噪声底 | D 12% | sus4 真实 |
| A7 | - | G 18%, 噪声底 4 倍 | 属七和弦成立 |

三度音是选择性缺席的, 缺席处正好是 sus 标记处, sus 是真实 voicing。原混音上判不出来, 人声与其他声部污染 chroma。这是分轨带来的最大收益。
